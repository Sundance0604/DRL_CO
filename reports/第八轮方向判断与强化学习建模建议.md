# 第八轮应当转向强化学习吗？——基于七轮证据的判断与建模建议

供研究讨论｜2026 年 10 月 9 日

本文是一份方向判断与拟实施方案，不是实验结果，也不代表已经启动训练。依据前七轮最终报告、相关 QA 及当前 single 模型接口撰写；既有实验保持只读。算法文献只用于解释方法选择，不作为本项目中 RL 必然有效的证据。

## 1. 我的判断：赞成从手工价值逼近转向 RL 实证比较

**我赞成将第八轮的主要研究问题转向一个受控的 RL prototype：在保留 MILP 可行性求解的前提下，直接学习提高完整闭环利润的战略信号。** 但我不赞成将理由写成“前七轮失败，所以传统方法不行，只能上强化学习”。

这里讨论的是同一个 current single 模型：不再把主要精力放在为资源价值选择简单函数族，而是转向用强化学习学习价值与决策；不是恢复旧模型。我赞成这一研究转向，尤其赞成让控制信号直接接受完整实现利润的检验。但必须明确 RL 学习的价值对象，不能只把 Chebyshev/Spline 换成神经网络，便认为此前的目标错位已经解决。

### 1.1 七轮证据为什么足以支持这次转向

已有证据形成了三个有用的出发点。

第一，**存在可利用的动态收益，也已经有强基准。** MC Table 的第一次策略改善在 W40/W80 上表现有力，第七轮独立 construction banks 的复核又支持其正向重复性；CA 则更敏感。因此，RL 不需要与一个过弱的短视方法单独比较，可以直接面对一个可信的简单竞争者。[第六轮 A][r6a]、[第七轮][r7]

第二，**预测任务与控制任务之间存在实质缺口。** 第五轮修正 freeze 后，ACTION 特征仍未稳定改善利润；B 的 W80 中，独立预测 MSE 变好，但闭环利润相对 base table 显著下降。这使“再选一种拟合器、更精确地回归同类标签”不再是我认为最优先的唯一道路。[第五轮][r5]、[B 报告][b]

第三，**反馈与接入问题已经足够具体。** full update 会在 CA 中恶化，阻尼能缓解部分现象；可分价格与独立联合动作评价在部分状态下存在分歧。现在可以提出一个清楚的替代假设：不要求网络精确复原某个人工资源标签，而让它学习什么战略信号经过现有 MILP 后，能够产生更好的最终行动。[A2][a2]、[第七轮语义审计][semantic]

### 1.2 这些证据还没有证明什么

- 未证明可分资源价值已达到表达上限。构造方差、支持不足、资源底座和查询语义仍是竞争解释。
- 未证明 joint rollout 已稳定优于价格策略。第七轮六组收益均值为正，但主 family 校正后未建立优势。
- 未证明神经网络能够学到比 MC Table 更好的控制信号，更未证明任何一个具体 RL 算法必胜。
- 未证明将原资源标签交给更大的网络，就能消除标签与控制目标的错位。

因此，我对这一建议的评价是：**赞成其方向，但应以“现在值得实证比较”为依据，不额外赋予“实验已经证明 RL 必要”的含义。** 这一区分是本报告自己的证据边界，不代表此前建议曾作出后一个断言。

第六轮的 MC policy iteration 本身属于广义近似动态规划／策略评价改进的研究脉络，不能笼统说此前与强化学习毫无关系。真正的新变化是：从估计资源边际表再接入优化器，转向以闭环回报训练参数化的状态依赖策略；不是简单换一个算法名称。

## 2. 第八轮应回答的科学问题

建议把核心问题写成：

> 在相同可见信息、相同 MILP 可行域和相同实现利润核算下，直接回报训练的状态依赖战略信号，能否稳定优于冻结 MC Table 及简单信号校准？

这里包含三个需要区分的贡献：

1. 从固定表变为状态依赖信号，是否有用？
2. 从局部监督标签变为完整回报训练，是否有用？
3. 若取得收益，是动态学习带来的，还是仅仅修正了表的整体幅度或时间倾斜？

第三点尤其重要。如果一个固定的价格修正就能达到相同收益，就不应把结果归功于复杂状态建模。相反，如果 RL 没有胜出，也要分辨是训练没有成功，还是接口根本无法表达所需动作。

我不建议把“验证 RL 的数学必要性”设置成启动前提。也不建议一开始同时改变状态、奖励、重定位权限、路线集合和优化窗口，否则即使利润提高，也不知道改进来自哪里。

### 2.1 “用强化学习研究 V”有两种不同含义

第一种是保留原来的资源边际 \(V_{\mathrm{res}}(t,u,q)\) 及其标签，只把拟合器换成神经网络。这通常仍是监督回归；即使使用仿真标签，也不因此自动成为新的 RL 控制方法。它可能提高表达能力，但不会自动修正资源注入底座、释放组语义和逐项可加的接入限制。因此，这不是我最推荐的第八轮主线。

第二种是从实际交互中学习策略的未来回报，例如：

\[
W^{\pi}(h_t)=\mathbb E_{\pi}\!\left[\sum_{k=t}^{T-1}r_k\mid h_t\right],
\]

其中 \(h_t\) 是允许使用的观测历史，末步奖励包含完整冷却。critic 以观测或记忆表示近似这个回报；actor 根据优势信号改善战略动作。这是本文推荐的 PPO actor–critic 路线：**仍然学习价值函数，但价值服务于直接改善控制，不再要求它先复原人工构造的资源边际标签。**

神经网络仍然是函数逼近器，所以转向 RL 不是“不做函数逼近”，而是改变学习目标、数据生成和策略改进的闭环。

另一条合理但不同的路线，是学习完整 post-decision value 或 joint-action Q，再据此选动作。它更直接面对联合价值，但一般的非线性网络不能直接作为原线性 MILP 的标量槽位系数；需要有限候选重排序、专门的优化编码或其他解码设计。若首个价格接口覆盖不足，这条路线值得采用，但不能与首版 PPO 的实现成本混为一谈。

保留 MC Table 作为残差底座，是为了利用强基准和便于回归，不是强制 RL 继续拟合它。它回答的是“在此底座上直接回报学习能否增益”；若要检验完全摆脱资源表，则应追加相同接口、无 MC 底座的独立对照，不能把残差结果当作从零学习的证明。

## 3. 总体架构：RL 决定战略信号，MILP 决定完整动作

推荐的控制链为：

> 公开订单与车辆状态 → 状态编码器 → 低维战略信号 → 原 single MILP → 完整合法联合动作 → 真实执行账本 → RL 更新。

严格区分两种“动作”：

- **RL 动作 \(a_t\)**：连续、低维的价格修正向量。
- **物理动作 \(d_t\)**：MILP 给出的完整匹配、路线、等待、承诺延续等决策。

设 \(\mathcal F(S_t)\) 为当前状态下原有合法联合动作集合，\(D\) 为求解器与固定提取规则构成的解码器，则：

\[
a_t\sim\pi_\theta(\cdot\mid o_t),\qquad
d_t=D(S_t,a_t)\in\mathcal F(S_t).
\]

MILP 负责运力、匹配、路线锚点与已有承诺等约束，RL 不直接生成完整的 \(x,y,z,w\)。可行性仍须由求解状态、整数动作编译和执行审计共同核对；不是用了 MILP 就可以省去验证。

现有代码中，`ValueProvider.marginal_release_value(time, hub, supply_slot, online_state_summary)` 已提供预求值标量接口；释放槽位约束也已限制车辆数量与前缀占用。适合把网络输出转换为求解前固定系数，而不把非线性网络直接嵌进 MILP。[接口源码][contracts]、[价值 MILP][planner]

首个对照应保留当前 H=1 资源价格策略的决策框架。RH4/RH8 可作为外部基准，但不应把“改成更长窗口”混在 RL 与 MC Table 的主比较中。当前实验禁用的重定位也不因加入 RL 自动开放。

## 4. 动作空间：推荐按枢纽输出有时间形状的价格修正

### 4.1 为什么不直接输出车辆—订单分配

直接输出所有车辆选择、路线和订单组合，会把大规模组合可行性一并交给网络。我们已经有经过多轮审计的 MILP，没有必要在第一个 RL 实验中重新学习这些硬约束。这样做也会让研究问题从“未来战略价值”变成“如何生成可行动作”，失去与七轮基准的连续性。

只输出一个全局价值乘数又可能过窄：它很难改变不同枢纽的相对偏好；而将系数加上共同常数，在总计价资源数固定时甚至可能完全不改变动作。首个原型应兼顾可解释性与实际动作影响。

### 4.2 推荐动作：每个 hub 两个有界连续参数

令枢纽数为 \(H\)，定义：

\[
a_t=\{a^{\mathrm{near}}_{t,u},a^{\mathrm{far}}_{t,u}\}_{u=1}^{H}
\in[-1,1]^{2H}.
\]

当前五枢纽实验中，这就是 **10 维连续动作**。两个分量分别控制较近、较远释放时刻的价格修正，不是分别决定“立即调车”和“未来调车”。实际车辆动作仍由 MILP 联合决定。

以冻结的非 bucket MC Table 为底座 \(V_{\mathrm{base}}\)，对求解器中的未来释放查询 \((\tau,u,q)\)，令：

\[
\ell(t,\tau)=\frac{\tau-t}{T-t},\qquad t\le\tau<T,
\]

\[
\lambda_{t}(\tau,u,q)=
V_{\mathrm{base}}(\tau,u,q)
+s_u\left[(1-\ell)a^{\mathrm{near}}_{t,u}
+\ell a^{\mathrm{far}}_{t,u}\right].
\]

当 \(\tau\ge T\) 时，自由资源价格仍为零。\(s_u>0\) 是预先冻结的美元尺度，可由训练 construction 的价值量级与一个正的最低尺度决定，再用工程验证集检查动作影响；不得根据正式收益反向调整。动作幅度、时间基函数和尺度选择规则需要在正式试验前冻结。

这一定义有几个好处：

- 零修正可以恢复原 MC 底座，便于回归与解释；必须沿用同一 solver、tie-break 和提取路径，不能只检查目标近似相同。
- 底座保留已有时间、hub、\(q\) 结构，RL 只学习状态依赖修正，避免从零探索所有资源价格。
- 输出可以降低也可以提高价格，不能任意把最终负价裁成零。
- \(q\) 的形状仍由底座提供，首版不学习逐 \(q\) 的独立参数，控制动作维数与自由度。

这属于“残差战略控制”的具体设计建议，灵感与在已有控制器上学习修正的 residual RL 思路相通；相关论文不构成本项目有效性的证明。[Residual RL][residual]

### 4.3 必须保留的限制

这些 \(\lambda\) 应称为**战略评分系数**，不再宣称它们是 \(V_{\mathrm{res}}\) 的无偏经济估计。RL 输出的价值是通过控制收益检验的，而不是必须匹配人工 MC 标签。

但仍使用释放组可分加和，因此不能表达任意联合动作价值。即使网络看到了整个订单池，输出仍可能无法使某些联合动作成为 MILP 最优。RL 可以改变状态依赖性，却不会自动消除线性评分接口的表达限制。

残差设计也不能消除底座的支持问题。底座在哪里插值、外推或回退，应逐查询记录；学习修正不能被称为获得了新的真实资源标签支持。若最终收益依赖大量不受支持的查询，应单独解释。

终端自由资源归零只约束战略系数，不代表日终之前采取的动作没有后续现金影响。那些影响必须进入实现奖励和冷却过程，而不能沿用旧 ACTION target 的错误解释。

### 4.4 其他动作定义为什么暂不作为首选

| 定义 | 优点 | 首版不优先的原因 |
|---|---|---|
| 每 hub 一个价格修正 | 更低维、容易解释 | 缺少释放时间形状；可作为简化对照 |
| 每 hub × 时间 × q 全部价格 | 表达更充分 | 动作维数、噪声和支持问题增加，难以归因 |
| fleet targets／期望库存 | 运营解释直接 | 需要定义时点、软偏差成本与可实现性，可能同时改变 decoder |
| 在完整候选动作集合中选一个 | 直接比较联合动作 | 依赖候选覆盖与多次求解；适合价格接口覆盖不足时的备选 |
| 直接输出完整匹配和路线 | 理论上最灵活 | 可行性难、空间大，改变研究对象过多 |

如果价格接口预检显示几乎不能改变动作，应暂停该接口上的大规模 RL 训练。届时可以改用合法完整候选集合上的离散策略，而不是靠扩大网络规模补救不可表达的问题。

## 5. 状态空间：网络看到运营状态，不能看到场景答案

### 5.1 环境完整状态与学习观测分开定义

仿真器内部知道所有未来订单，并不意味着控制器可以知道。定义：

- \(S_t\)：仿真完整状态，用于转移与核验，可能包含不可见未来。
- \(o_t\)：决策时刻可观测信息的编码，只能由已公开订单、车辆与承诺、公开参数、允许的历史生成。

信息处理顺序应固定为：完成当前时点应发生的到达与交付，公开当前预约订单，然后形成观测，选战略动作，再求解与执行。不能在形成 \(o_t\) 时先推进未来一步。

### 5.2 建议的观测内容

| 信息块 | 第一版建议字段 | 要避免的问题 |
|---|---|---|
| 全局时间与公开参数 | 当前期、剩余决策期；车队规模；公开容量、成本和时间规则 | 不用隐藏的订单总数推导“剩余必到订单数” |
| 公开订单集合 | origin/destination、载荷、收入、booking/ready/deadline、当前等待、剩余 slack、是否已分配及履约状态 | 不输入未来尚未公开的 shipment、实际剩余 OD 配额 |
| 车辆与承诺集合 | 当前 hub／路段、phase、下一事件 ETA、剩余路线、在车货物、承诺上下客、逐段剩余容量、最终自由释放 hub/ETA | 中途到站不当作完全自由车辆；idle 与 incoming 不重复计数 |
| hub 级摘要 | 空闲车、不同未来释放时间段的供给、公开未服务需求及载荷、紧迫订单、已知净流入流出 | 不只用一个 imbalance bucket 替代所有状态 |
| 网络结构 | 公共距离、旅行时间、hub 连接和可达性 | 不用样本 ID 代替地理结构 |
| 可观测历史与先验 | 已公开到达的累计量／近期 OD 统计；只由训练数据拟合的到达先验 | 不读取生成器隐藏随机数、scenario seed 或实际未来 |
| 底座信息 | 当前可查询 MC 价格、支持计数及回退标识 | 测试集不能参与重估底座、标准化或先验 |

“未来车辆释放”仅指由现有承诺可推算的释放，而不是由尚未选定路线或未来订单推出来的结果。候选路线的释放信息可供 MILP 计算，但不能把最终优化解当作选战略动作之前的观测。

### 5.3 表示方式：不要又把关键状态压成几个总数

第一版建议采用小型集合编码器：分别编码公开订单与车辆承诺，再与 hub 摘要、全局时间拼接；固定网络中的 hub 身份可以编码，订单和车辆的任意编号不应成为捷径。变长集合使用 mask，避免依赖输入排列。保留所有当前公开订单；若因预算需要裁剪，应记录确定规则和被丢弃信息，不能静默只取最有利的订单。

车辆承诺不能只压缩为“还有几辆车即将到达”。剩余路线和不同路段容量决定车辆是否还能接单，丢掉这些信息可能使策略分不清可用与不可用的供给。MILP 仍使用完整物理状态，编码器是否丢失控制相关信息需要单独测试。

不必一开始上大型 Transformer 或复杂 GNN。可以使用小型共享编码网络与聚合，配合固定网络特征；聚合表示仍有信息损失，不把它宣称为严格充分状态。

此外，隐藏需求过程不一定在简单摘要下满足 Markov 性。原场景有固定总量及抽样结构，公开到达历史可能改变对未来的判断。应保留公开历史统计，必要时使用轻量记忆；若首版只用当前摘要，应明确这是部分可观测的近似控制问题，而不是宣称已经构造精确 MDP。

### 5.4 标准化和跨工况范围

时间、距离、载荷和金额用训练数据确定的固定尺度标准化。验证和正式场景不得更新均值方差；先验、特征选择与网络结构也不能根据正式结果重选。

首轮可以分别训练各工况模型，以检验能否在工况内稳定改善，然后单独研究跨工况泛化。不同工况分别训练是条件化模型，不是一个通用策略。若训练统一策略，应预先声明条件采样权重；不能按各工况利润做未披露的奖励标准化后，仍宣称优化了原来的总体平均美元利润。

## 6. 奖励：只优化完整冷却后的实现利润

### 6.1 明确优化目标

推荐目标为：

\[
\max_\theta\;\mathbb E\left[J_{\mathrm{realized}}^{\mathrm{full\ cooldown}}\right].
\]

完整利润包括最终实际交付收入、实际载货与空驶成本，以及原有等待、积压和取消等账本成本。沿用冻结业务定义，不因加入 RL 增加另一套服务率权重或漏单罚项。[实现账本源码][accounting]

必须区分：MILP 的 booked objective、网络输出的战略 bonus、RL 的 realized reward 是三种不同量。战略 bonus 和 tie-break 不是实际现金，不能计入 reward；订单分配时预记的运费，也不能与交付收入重复奖励。

### 6.2 推荐逐期账本增量，末步自动完成冷却

设 \(L_t\) 是按统一边界记录的累计实现利润，整日初始 \(L_0=0\)。对非最后决策期：

\[
r_t=L_{t+1}-L_t.
\]

最后一个决策期执行完当前动作后，环境自动禁止新增战略决策，按原日终规则处理订单，并执行所有已有承诺直到完成。最后一个奖励返回：

\[
r_{T-1}=J_{\mathrm{full\ cooldown}}-L_{T-1}.
\]

因此必须逐 episode 核验：

\[
\sum_{t=0}^{T-1}r_t=J_{\mathrm{full\ cooldown}}.
\]

这样学习器仍只有日内决策序列，日终后的现金不会被丢掉，也不需要给已经无权决策的冷却时点采样动作。事件恰好发生在时点边界时，收入、成本和 arrival 的先后必须与原账本一致，不能在相邻 reward 中重记。

完整 episode 可采用 **\(\gamma=1\)**，以保持有限日内、不折扣美元利润的目标。直接套用折扣因子会重新偏好早收入／晚成本，可能重复制造此前试图消除的终端偏差。只要是完整 episode 的真实终止，终态 bootstrap 为零；技术性截断、求解故障或未完成冷却不能伪装成真实终止。

### 6.3 不建议首版添加的奖励

- 不额外奖励“接一单”“少空驶”“高服务率”，这些可能改变业务目标，或重复计算已有收益与成本。
- 不把 \(V\)、\(J-g\)、rollout ACTION label 或 critic 预测当作实际 reward。
- 不把每期相对另一条 M0 轨迹的利润差，直接当同状态优势。两条策略的状态会分叉，不能混用。
- 不按每条 episode 的自身收益范围缩放，也不裁剪大额负奖励，否则目标不再是原利润。

可使用训练前冻结的正数尺度 \(c\) 将奖励改成 \(r_t/c\)，但最终仍还原美元比较。critic baseline 和 advantage 标准化属于梯度估计工具，不应被包装成新的运营奖励。若以后引入风险或服务约束，应另行声明目标变化，而不是以 shaping 名义悄悄加入。

### 6.4 不要混淆两种 value function

RL critic 估计的是给定当前观测与策略的未来总回报，例如 \(W_\psi(o_t)\)；原 MC Table 估计的是资源注入的边际利润。二者即使都称 value，也不是同一个估计量。不能把 critic 的一个标量不经定义直接替换所有资源槽位价格。

## 7. 算法选择：PPO 作为首选，稳健性仍需在本项目验证

结合本项目特点及当前讨论，建议把小型 **PPO actor–critic** 定为首个主算法，有界连续动作分布输出上述战略修正。PPO 通过采样和策略梯度更新，不要求对 MILP 最优解求导；其 clipped surrogate 旨在限制过大的策略更新，但不是硬性信赖域约束。[PPO 原论文][ppo]

选择它是针对本项目的工程判断，不是“PPO 已被证明优于 SAC”：

1. 价格到整数动作的映射往往是分段不变的，并在切换边界跳变。先用基于实际采样回报的更新，更容易审查价格究竟有没有改变物理动作。
2. 当前首先需要解决奖励、观测与执行链是否一致，而非同时引入复杂 replay buffer 与离策略目标。
3. 可以控制更新幅度，并记录策略分布变化；但 PPO 的 clipping 不是单调改进或安全性的证明，不能当成 A2 阻尼的理论替代。

SAC 的离策略回放可能在昂贵仿真下更节省新交互，其最大熵框架也提供探索机制。[SAC 原论文][sac] 但在本项目中，需要额外警惕：不同价格可能解码成同一个动作，价格空间的高熵不等于物理行为丰富；critic 在整数动作切换处的近似梯度可能不可靠。这是需要试验的风险，不是排除 SAC 的定理。

因此，SAC 可作为后续预算效率对照，首版不必把算法选择扩成大矩阵。如果 PPO 的采样成本在工程 pilot 中无法承担，应公开调整方案，而不是在正式集上试遍算法再挑赢家。

对于“PPO 比较稳健”，我同意把它作为合理的工程选择倾向，而非普遍性能结论。本项目的验收仍应查看近似 KL、clip fraction、策略熵、critic 误差、动作边界饱和、实际物理动作变化率和独立验证利润。连续参数熵很高而解码动作不变，并不是探索成功；PPO 更新幅度受到抑制，也不代表所有保护工况都安全。任何 KL 早停或训练停止规则都应在正式评估前设定。

实现上还应注意：若用 squashed Gaussian 或其他有界分布，训练 log probability 必须与实际动作变换一致。不能训练时按未裁剪动作记概率，执行时却截断。零修正的确定性回归要单独测；随机策略初始化均值为零，不代表每次采样都执行 MC 基准。

## 8. 第八轮的最小可信实验，而不是一次算法大拼盘

### 8.1 先过三个入口检查

**账本检查。** 每个训练 episode 的 reward 总和与最终 realized ledger 一致，所有承诺冷却完成；动作编译、容量和信息可见性检查继承当前核验链。这里只是复用协议，不向冻结实验目录写新数据。

**零信号回归。** 使用相同 MC 底座、同一价值 MILP 与 solver 设置，零修正恢复基准。需要比较完整动作与后续轨迹；如果存在非唯一最优解造成差异，应固定并披露 tie 规则，不能用“利润差不多”掩盖 decoder 变化。零 MC 底座与原 M0 是否逐动作相同，应另做检查，不能假设不同 MILP 表达在 tie 下必然一致。

**动作可控性。** 在训练／诊断状态上尝试预先确定的价格扰动，记录实际动作 hash、释放位置与时间是否变化。若绝大多数扰动都没有行为影响，先诊断尺度、共同平移抵消与接口覆盖；不直接花大预算训练。还可检查原联合候选中哪些能被此评分接口选出：不被有限扰动找到，不等于数学证明不可表达，但足以作为预算决策的预警。

### 8.2 主比较保持紧凑

| 方法 | 用途 |
|---|---|
| M0 | 保留短视参照，不作为唯一对手 |
| 冻结非 bucket MC Table | 主要强基准；来源银行与 hash 明确，不事后挑选 |
| 简单校准策略 | 用训练／验证集调固定或仅随时间变化的同类价格修正，辨别是否只是幅度校准 |
| RL 残差战略策略 | 同一 decoder 与底座，学习状态依赖修正 |
| RH4／RH8 | 提供滚动前视的实用参照，单独报告求解成本 |

不必将所有旧 Chebyshev、Spline、Bayesian、bucket 和 PI 组合重新跑成大矩阵。旧结论作为机制背景；本轮只保留能辨别新假设的对照。

### 8.3 样本、预算与评价

训练、模型选择和正式评估使用全新且不重叠的场景集合；历史正式集已经被反复阅读，只宜用于回归，不宜继续作为唯一“未见测试集”。训练过程不能从正式目录载入状态、目标或归一化统计。复用冻结 MC 表是允许的先验，但其构造数据来源必须披露，不能把新 RL 训练数据与旧基准的差异隐藏起来。

至少重复多个独立训练随机种子；可把五个训练重复作为预算起点，再依据独立 pilot 的耗时和方差冻结实际方案，而非承诺这个数量足以确证。正式场景数依据最小有意义美元效应与训练、场景两层方差规划，不机械沿用此前的场景数。

统计保留训练模型和测试场景两个维度，同一测试场景用于方法配对；不能把所有训练 seed × scenario 直接当独立样本。若底座只用一个银行，结论是条件于该底座；要声称更广的鲁棒性，还需要独立底座银行重复。正式报告均值、区间、失败与尾部表现，不只给最好 seed。多 seed 与不确定性报告的必要性也与 RL 评估方法研究一致。[RL 评估文献][evaluation]

超参数与 checkpoint 用验证集选择，正式前冻结。主比较预先限定为 RL 对 MC Table 及简单校准，并预设保护工况与多重比较规则；不把“未显著下降”写成安全非劣。

记录实际完整 episode 数、MILP 调用数、离线训练 wall time、在线策略与 solver 延迟。工程 pilot 决定能承受的预算，不在报告里虚构一个已经测得的训练耗时。PPO 与 SAC 若进入同轮对照，应同时给等交互预算与实际时间，不能只比较推理速度。

### 8.4 判定结果时，我会关注什么

- **若 RL 优于 MC 和简单校准，并在重复训练、新场景下保持收益：** 支持状态依赖直接回报学习的增量价值，而非证明 MC 普遍失效。
- **若 RL 只优于原表，不优于简单校准：** 主要证据是定价幅度／时间形状需要校准，不足以支持复杂学习必要。
- **若训练收益上升而新场景下降：** 优先考虑过拟合、奖励／信息泄漏及分布差异，不立即扩网络。
- **若战略输出变化很大但物理动作基本不变：** 先检查接口平坦区和解码覆盖，不把它称为 RL 训练不够久。
- **若物理动作丰富但利润没有稳定改善：** 区分优化失败、观测不足与动作接口限制；没有一次实验就能排除所有 RL 方法。

## 9. 如果不做 RL，我最推荐什么方案？

我不主张无限期推迟 RL，但如果当前预算或入口检查不支持训练，替代路线应是 **“MC 底座校准 + 条件未来下的选择性联合 rollout”**，而不是再增加一个拟合函数族。

### 9.1 MC 底座校准

保持强 MC 基准，补足高使用率、低支持的查询，独立重复 construction bank；对训练注入 \(q\) 与在线释放组 \(q\) 的含义做单因素对照。价格尺度和时间修正可以用低维无梯度搜索、交叉验证和直接实现利润选择，不需要神经网络。此时它属于直接策略搜索或校准，不应把它包装成更复杂的 RL 结果。

### 9.2 选择性 joint rollout

在满足预先规定的动作分歧或不确定性条件时，生成少量完整合法候选，用独立未来评估，再执行整个当前联合动作。其他状态沿用 MC 基准，从而将计算花在可能影响决策的位置。

selection 与独立 assessment 仍必须分开；触发规则只在训练／诊断集确定，不能根据正式收益挑“值得 rollout”的状态。未来生成只能用公开信息与冻结先验，并需检验不同合法生成假设的敏感性。应做真正的整日闭环部署评价，不能把第七轮的局部一次替换收益当成部署收益。

### 9.3 如果真正的问题是可分价格表达不足

可先研究有限候选联合动作选择、少量明确的资源耦合项，或用高精度 rollout 对候选进行直接排序；这些方法比“更精确地预测同一资源边际”更直接面对联合决策。

但耦合项和候选机制也需要同信息、同预算比较，不能因为观察到交互就默认它们会提升利润。若以后用网络蒸馏 rollout 排序，还应说明是代理分布下的监督策略学习，不是已经绕开所有目标错位。

## 10. 最终建议与边界

我的首选是将前七轮成果变成新学习方法的基准与约束，而不是继续把更换资源价值拟合器作为唯一道路：

> **以 MC Table 为底座，以 MILP 为动作解码器，以完整实现利润为目标，启动一个低维残差战略 RL 原型；同时保留简单校准与高精度联合 rollout 作为竞争和诊断工具。**

这种安排能回答新问题，也保留了此前最强的基准。RL 路线不需要先证明数学上的必要性，却必须接受公平对照和失败检验；保守路线不应成为永远延迟比较学习控制的理由，也不应被弃置为“过时方法”。

本轮不需要先证明“神经网络比一切表格更强”。只需要回答一个更清楚、也更有价值的问题：**在当前可行决策结构下，直接学闭环收益，是否比估计资源边际再间接控制更有效？**
